# interactive-v1.2 实施与验收冻结方案

基线：当前工程interactive-v1.1-corrected，328项清单SHA-256 de66f76fa0b245aa2fd112023214fa913fb4509eab4b88f4d848c6b435136c57。保留用户修改、旧队列归属与逐设备批量修复；不重写密码、H1–H4、记录层，不重采M5正式1000次。

网关原状态：InitDemo/config.NewRuntime可生成、配置和使用独立签名/协商密钥；management.Apply和secctl rotate仅device；generic revoke/retire仅登记状态，不是网关业务闭环。新增独立management.GatewayPlan及live网关维护入口，不删除设备角色判断。

单写者：Manager.adminMu串行；同一trust禁止其他CLI/进程并行写，底层CAS不宣称跨进程文件锁。网页高级身份管理仅本机owner；确认action:GW001:ALL，Host/Origin/Cookie/CSRF及8KiB严格JSON不变。无新密码或信任分发协议。

维护策略：关闭新准入；生成随机新key_id、生成并回读校验签名与协商私钥、公钥绑定；取消所有设备工作者、关闭所有已接纳TCP（包含握手中连接），有界5秒等待旧会话与队列清理；未写出旧任务failed/cancelled，可能写出但无回执保留unconfirmed，终态不复活，不变更旧SID。CAS检查旧revision/世代/双key_id/生命周期；重新加载真实本地runtime与受控trust；成功才恢复准入，设备明确连接完成新H1–H4；清理退休目标key_id。

准备/文件失败不提交旧可信世代；恢复准入但已经关闭的会话需明确重连。排空超时不提交、保持准入关闭。CAS失败保留当前可信状态（若并发吊销则继续拒绝），允许操作员按可信状态明确重连。提交后Reload/加载失败保持准入关闭；不回滚旧密钥。清理失败pending，不回滚新世代。重试清理只能处理目标网关退休/孤立文件，活动当前key_id保留；不恢复吊销信任。吊销保留文件供调查，退役才删除当前/退休材料；不是物理擦除。平台是本机模拟受控trust更新，不冒充远程PKI。

真实证据：双端事件保存握手时不可变gateway_authenticated，设备来自Channel.PeerSnapshot，网关来自实际握手runtime的可信快照；不把后续注册表值回填旧会话。单台/20台新世代遥测和ACK正例、旧同ID密钥TCP握手拒绝、旧请求跨世代拒绝、吊销/退役/重启持久拒绝。隔离失败测试使用实际文件错误/CAS交错/提交后删除新文件/清理读取失败，测试操作只在_test.go，不提供生产跳过验证开关。

易用性：简洁模式默认开始使用/收发数据/设备/记录/帮助，高级保留总览/身份迁移/安全实验/性能来源。五步授权→连接D001→发送温度→设周期→确认。两任务卡当前结果紧邻按钮；幂等ID自动，SID/revision/JSON折叠技术详情；秒精确转换100..60000ms，非法小数不舍入。手动回执与自动源/最近接收分开，表单草稿/焦点不被轮询替换；刷新不启动、不重发。

操作状态来自实际队列/写出/处理/ACK；HTTP成功不当对端成功，ACK超时可能已执行。32临时队列与256累计操作提示分开，换钥不清累计。授权1小时，不自动续期，失联禁写和在线未知；退出是owner+CSRF受控关闭。日志仅2000有界事件，设备/观察端/阶段筛选及20条分页，固定cursor范围避免跳页；明确更新范围，默认脱敏，导出同一过滤范围及选择元数据。
