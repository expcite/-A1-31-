# 题目要求与实现映射

**要求来源：用户上传的《（A1-31）园区边缘设备国密与后量子混合安全通信软件设计实现(2).docx》，共 2 页。**
这里保留原题六项密码功能要求和创新要求的组织方式；右列是本项目提出的实现映射，不是原题指定架构。

|原题条目|要求概要|对应模块/阶段|
|---|---|---|
|场景与定位，第1页|资源有限、存量/新型设备共存、渐进迁移；软件仿真，不要求自研底层算法或硬件|Go+TCP+模拟设备；M0-M6|
|1，第1页|设备、网关、会话密钥生成/配置/使用/轮换/吊销/销毁；长期与临时分离；密钥不入日志|identity、secctl、会话管理；M1/M4|
|2，第1页|双向身份认证；会话同时依赖 SM2 密钥协商与后量子 KEM；基于 SM3 的 KDF 绑定身份/随机数/算法标识/握手摘要；不能简单截断或异或|cryptosuite、handshake；M1-M3|
|3，第1页|SM4 认证加密保护遥测/控制；机密性/完整性/来源认证/抗重放；同密钥 nonce/计数不重复；定期换钥与安全重连|record、app、会话管理；M2-M4|
|4，第1页|传统/混合共存，默认优先混合；声明混合支持后删除/篡改协商字段要失败；说明迁移与防降级|policy+认证 transcript+信任登记；M3/M4|
|5，第1页|至少1网关20模拟设备；两模式分别测握手时延/报文长度/峰值内存/CPU时间/吞吐/连续1000次握手成功率；保留原始结果与脚本|cmd/bench、scripts、results；M4/M5|
|6，第1-2页|威胁模型与安全目标；先存储后分析、中间人、重放、降级、随机数失效、长期密钥泄露、拒绝服务；源代码/构建/流程/密钥状态/测试报告/组件版本许可证|docs；全阶段|
|创新，第2页|至少一项可验证改进；不可削弱认证/关闭防降级换速度；与传统国密和公开混合方案或同类实现比较|可审计测试候选；M5/M6|

重要：编译成功、明文20设备实验、AES 测试替身、单个密码算法的 round-trip，均不能单独满足原题完整安全联调要求。
